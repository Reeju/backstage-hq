# T-17: Spikes: Q-T1, Q-V2, Q-V3, Q-V5

**Tier:** A (each answer can change an approved design; run by the `architect`, not a builder)
**Links:** Architecture section 28.2 (Q-T1, Q-V2, Q-V3, Q-V5), section 13 ("Sending exactly once"),
section 26 (S2, S7), ADR-005, ADR-009, ADR-011, ADR-015; PRD NFR-031, NFR-035, FR-011, FR-123 AC3.
**Depends on:** owner prerequisites only: a Google Cloud project with the Gmail API enabled, an OAuth
client in testing mode, and a test Gmail account; Bedrock model access requested in ap-south-1 in the
staging AWS account. Can run at any time, in parallel with everything. If CR-001 is adopted before this
runs, skip Q-V2, Q-V3 and Q-V5 (plan section 10).

## Why
Four platform facts were assumed in the architecture and must be checked before the features that rely
on them are planned. Each costs an hour or two now; finding out later would mean redesigning a feature
that is already built.

## Files to touch
- `spikes/q-t1-gmail-message-id/send_and_find.py`, `spikes/q-t1-gmail-message-id/README.md`
  (throwaway script outside `app/`, never deployed, never imported; uses its own `uv` script header)
- `docs/iterations/01-walking-skeleton/spike-results.md` (the findings: one section per spike)
- No changes to `app/`, `infra/` or any approved document. If an answer is "no", the result file
  contains the proposed architecture edit for the owner to approve separately.

For each spike `spike-results.md` states: the answer (yes/no/partly), the evidence, **what it decides**,
and, if "no", the fallback and the exact architecture/ADR edit to propose:
- Q-T1 "no" → fallback: before any retry, search Sent for the same recipient and subject in the last 24
  hours and compare a stored content fingerprint; proposed edit to architecture section 13 and ADR-009.
  Needed before iteration 5 is planned.
- Q-V2 "no" → choose a model version that does not need it, or reopen S2 (Anthropic API direct with zero
  retention, or Gemini on Vertex); proposed edit to ADR-011. Needed before iteration 8 and before beta
  (NFR-035).
- Q-V3 "no" → Postmark inbound, or SES receiving in another region, listed on the privacy page
  (NFR-006); proposed edit to ADR-015 and section 26 S7. Needed before iteration 5.
- Q-V5 "no" → ClamAV container (ADR-005 alternative) with its memory and update cost; proposed edit to
  ADR-005 and section 24. Needed before iteration 8.

## Acceptance criteria
- Given each of the four spikes, when finished, then `spike-results.md` has a yes/no answer, dated
  evidence with links, what it decides, and (if "no") the fallback and proposed document edit.
- Given the spike script, when inspected, then it holds no credentials (it reads them from a local file
  ignored by git), and the test accounts' tokens are revoked at the end (recorded).
- Given the AWS resources created for Q-V5 and any Bedrock settings changed, when the spike ends, then
  they are deleted or restored (recorded).

## Tests that prove it
- No automated tests (research only, nothing shipped). The reviewer checks `spike-results.md` against
  the evidence, and `git diff` shows no change under `app/` or `infra/`.
