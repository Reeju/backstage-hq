# T-08: Background jobs, worker and heartbeat

**Tier:** B (the design is fixed in ADR-006; workspace context reuses T-04's helper)
**Links:** NFR-012 (foundation), ADR-006, architecture section 13, section 22 (heartbeat).
**Depends on:** T-04.

## Why
Reminders, syncs, AI work and sends will all run in the background. The queue lives in PostgreSQL so a
job is queued in the same transaction as the change that caused it: if the change rolls back, the job
never existed. A heartbeat tells us within 20 minutes if the scheduler stops.

## What to build (decisions already made)
- **Wrapper only.** No module imports `procrastinate` except `bhq.jobs` (add an import-linter contract).
  Public API in `bhq/jobs/api.py`:
  - `@job(queue, *, workspace_scoped=True, lock=None, retry=RetryPolicy(...))` registers a task.
    Queues: `realtime`, `ai`, `bulk`, `scheduled` (architecture 13). Default retry: exponential backoff,
    5 attempts, max 30 minutes apart.
  - `defer(task, *, workspace_id=None, **kwargs)`: must be called inside a transaction; uses
    Procrastinate's Django connector, so the job row commits or rolls back with the caller's
    transaction. Raises if `workspace_scoped` and no `workspace_id`.
  - At run time a workspace-scoped job body runs inside `workspace_context(workspace_id)` (T-04), so
    RLS applies to every query it makes. Jobs that are not workspace-scoped (housekeeping on global
    tables) run with no workspace setting and therefore cannot read any business row.
  - Job arguments are IDs and small scalars only; never message text, codes, tokens or PAN (the
    reviewer checks this; a unit test rejects `str` arguments longer than 200 characters).
- **Periodic tasks** (`periodic.py`): `@periodic(cron, queue="scheduled")` wraps Procrastinate's
  periodic deferrer. First periodic tasks:
  - `jobs.heartbeat` every 5 minutes: HTTP GET to `HEARTBEAT_URL` (Healthchecks.io) with a 5-second
    timeout; no-op when unset; failure is logged, never raised.
  - `jobs.purge_finished_jobs` daily: delete succeeded Procrastinate job rows older than 7 days.
- **Worker** (`run_worker`): one process running all four queues for the lean beta, concurrency from
  settings (default 4), graceful shutdown on SIGTERM (finish the current job, up to 30 s), logs each
  job start/finish with `job_id`, task name, queue, `workspace_id` and duration (no arguments).
  Splitting queues into separate processes is deferred until imports exist (iteration 9).
- Procrastinate's tables are platform tables (no `workspace_id`, so outside RLS by design; architecture
  6.5). Their grants come from T-04's default privileges.

## Acceptance criteria
- Given a transaction that defers a job and then rolls back, when the worker polls, then no job exists.
- Given a committed deferral, when the worker runs, then the job runs once and succeeds.
- Given a workspace-scoped job for workspace A, when its body reads a scoped model, then only A's rows
  are visible; given a job for A that tries to read B's row by ID, then nothing is found.
- Given a workspace-scoped task deferred without `workspace_id`, when `defer` is called, then it raises.
- Given a job that fails, when retried, then it follows the backoff policy and stops after 5 attempts.
- Given `HEARTBEAT_URL` set, when the heartbeat task runs, then exactly one GET is made; given the URL
  is unreachable, then the task logs a warning and does not fail.
- Given SIGTERM during a job, when the worker stops, then the current job finishes first.
