# T-01: Project skeleton and local environment

**Tier:** B
**Links:** ADR-001 (Django + HTMX), ADR-019 (environments), NFR-042 (health endpoints), architecture
sections 3, 5, 8 (Health), 19 (Local).
**Depends on:** plan decision D1 approved (package layout `app/bhq/<module>/`).

## Why
Every later ticket needs a Django project that starts, a local database, and the agreed folder
layout. Nothing here is business logic.

## What to build (decisions already made)
- **Python 3.13, Django 5.2 LTS**, managed with **uv** (`uv sync --frozen` must work). Dependencies
  in this ticket only: `django~=5.2`, `psycopg[binary]~=3.2`, `django-environ`, `gunicorn`,
  `whitenoise`. Dev group: `pytest`, `pytest-django`, `pytest-cov`, `factory-boy`, `time-machine`,
  `hypothesis`, `ruff`, `mypy`, `django-stubs[compatible-mypy]`, `import-linter`. Later tickets add
  their own.
- **Settings** read from environment variables (`django-environ`). `base.py` holds everything common;
  `test.py` is used by pytest; `staging.py` and `production.py` set `DEBUG=False`,
  `SECURE_SSL_REDIRECT`, `SECURE_HSTS_SECONDS=31536000`, `SESSION_COOKIE_SECURE`,
  `CSRF_COOKIE_SECURE`, `SECURE_PROXY_SSL_HEADER` (behind the ALB), `ALLOWED_HOSTS` from env.
- `AUTH_USER_MODEL = "accounts.User"` is set in `base.py` now, but **no app with migrations is added
  and no migration is created in this ticket** (the user model arrives in T-04 and must be in the
  first migration). `INSTALLED_APPS` keeps only `django.contrib.contenttypes` and `staticfiles`. Do
  **not** add `django.contrib.auth` or `django.contrib.sessions` (T-04 and T-10 add them together with
  the custom user and session models), and never `django.contrib.admin` (staff sign-in with MFA comes
  later; the admin must not be reachable).
- `DEFAULT_AUTO_FIELD` is irrelevant (models use UUIDv7 keys from T-04); set it to `BigAutoField`.
- Time: `USE_TZ=True`, `TIME_ZONE="UTC"` (business dates use the workspace time zone later).
- **Health endpoints** in `app/config/health.py`: `GET /health/live` returns 200 `{"status":"ok"}`
  without touching the database; `GET /health/ready` returns 200 with `{"status":"ok","commit":
  "<GIT_SHA env>"}` only if a `SELECT 1` succeeds and there are no unapplied migrations
  (`MigrationExecutor(connection).migration_plan(...)` is empty), else 503 with a reason code (never a
  stack trace).
- **Static files:** Tailwind **standalone CLI** (no Node), pinned version, binary downloaded in the
  Dockerfile with a SHA-256 check; output `app/static/build/app.css`, served by WhiteNoise.
- **Dockerfile:** multi-stage, `python:3.13-slim` pinned by digest, `uv sync --frozen --no-dev` in the
  final stage, runs as a non-root user, builds Tailwind and `collectstatic`, default command
  `gunicorn config.wsgi --bind 0.0.0.0:8000`. Must build for `linux/arm64` and `linux/amd64`.
- **Local environment (`compose.yaml`):** `db` (`postgres:17`), `mailpit` (SMTP 1025, UI 8025),
  `web` (`manage.py runserver`, code mounted). T-04 adds role bootstrap; T-08 adds `worker`.
- `pyproject.toml` holds the config for ruff (line length 100, rules `E,F,I,B,UP,S,DJ`), mypy (django
  plugin; strict list starts empty and grows per module), pytest (`DJANGO_SETTINGS_MODULE=
  config.settings.test`, `--strict-markers`), coverage.

## Acceptance criteria
- Given a fresh clone, when the developer runs `docker compose up` in `app/`, then
  `http://localhost:8000/health/live` returns 200 and `/health/ready` returns 200 once the database is up.
- Given the database is stopped, when `/health/ready` is called, then it returns 503 with
  `{"status":"unavailable","reason":"database"}` and no stack trace.
- Given `uv run ruff check`, `uv run mypy .` and `uv run pytest` in `app/`, when run, then all pass.
- Given `docker build` for `linux/arm64`, when run, then the image builds and starts as a non-root user.
- Given any URL under `/admin/`, when requested, then it returns 404.

## Tests that prove it
- `app/tests/test_health.py::test_health_live_returns_ok` (integration): 200 and body.
- `app/tests/test_health.py::test_health_ready_ok_when_db_up_and_migrated` (integration).
- `app/tests/test_health.py::test_health_ready_503_when_migrations_pending` (integration, patches the
  migration plan to non-empty): 503, reason `migrations`.
- `app/tests/test_health.py::test_admin_not_routed` (integration): `/admin/` is 404.
