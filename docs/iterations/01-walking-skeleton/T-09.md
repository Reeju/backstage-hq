# T-09: Structured logs, Sentry and redaction

**Tier:** B
**Links:** NFR-025 (no tokens in logs), NFR-048 groundwork (the `q` field is already dropped);
ADR-018; architecture sections 22 (Errors, Logs), 25.
**Depends on:** T-01.

## Why
From the first real sign-up, phone numbers, codes, PAN and bank numbers pass through the app. None of
them may reach technical logs or Sentry. This ticket sets up one logging path for web and worker with a
filter that removes them, and tests that prove it.

## Files to touch
- `app/config/logging.py` (structlog configuration, processors)
- `app/config/sentry.py` (init, `before_send`, `before_breadcrumb`)
- `app/config/middleware.py` (`RequestIdMiddleware`)
- `app/bhq/common/redact.py` (pure functions, no Django imports)

- Tests: `app/bhq/common/tests/test_redact.py`, `app/tests/test_logging.py`, `app/tests/test_sentry.py`

## What to build (decisions already made)
- **structlog** JSON to stdout (ECS ships stdout to CloudWatch), with fields: `timestamp` (UTC ISO),
  `level`, `event`, `logger`, `request_id`, `job_id`, `workspace_id`, `actor_kind`, `release` (git SHA).
  Django's own loggers and `logging` calls go through the same processors.
- `RequestIdMiddleware`: takes `X-Request-ID` from the ALB if it is a valid UUID or token of up to 64
  safe characters, else generates one; binds it to structlog `contextvars`; returns it in the response
  header. T-04's middleware binds `workspace_id`; T-08's worker binds `job_id`.
- **`redact.py`** (used by both the log processor and Sentry):
  - Drop by key (case-insensitive, also nested in dicts and lists): `password`, `code`, `otp`, `token`,
    `access_token`, `refresh_token`, `authorization`, `cookie`, `set-cookie`, `sessionid`, `csrftoken`,
    `pan`, `gstin`, `account_number`, `body`, `q`, `secret`, `api_key`, and any key ending `_enc`.
    Replaced by `"[redacted]"`.
  - Mask by value pattern anywhere in strings: PAN `\b[A-Z]{5}[0-9]{4}[A-Z]\b` → `[pan]`; GSTIN →
    `[gstin]`; Indian mobile numbers (`+91` or 10 digits starting 6–9) → keep the last 2 digits
    (`+91********10`); email addresses → keep the first character and the domain (`a***@example.com`);
    bearer/JWT-looking tokens (`eyJ...` and strings of 32+ base64/hex characters) → `[token]`; bank
    account numbers are covered by key drop (digits alone are too ambiguous to pattern-match).
- **Sentry:** `send_default_pii=False`, `max_request_body_size="never"`, `include_local_variables=False`,
  `before_send` drops `request.data`, `request.cookies`, `request.headers.Authorization` and applies
  `redact.py` to the message, exception values, `extra` and breadcrumbs; `before_breadcrumb` drops SQL
  query parameters. Environment and release set from env. Disabled when `SENTRY_DSN` is empty.
- Django: `sensitive_post_parameters` and `sensitive_variables` are used by every auth view (T-10/T-11
  must apply them; the reviewer checks).

## Acceptance criteria
- Given a log call with `token="ya29.a0Af..."` or a nested `{"auth": {"refresh_token": "..."}}`, when
  logged, then the output contains no part of the token (NFR-025).
- Given a log message containing a PAN, a GSTIN, a +91 mobile number or an email address, when logged,
  then they appear only in masked form.
- Given an exception raised in a view whose POST body has `code=123456` and `pan=ABCDE1234F`, when
  Sentry's `before_send` processes the event, then neither value is present anywhere in the event.
- Given a request, when it is logged, then the line is valid JSON with `request_id`, and the response
  carries the same `X-Request-ID`.
- Given staging or production settings, when the app starts, then logs are JSON; locally they are
  readable console lines.

## Tests that prove it
- `test_redact.py::test_drops_sensitive_keys_nested` (unit, parametrised over every key).
- `test_redact.py::test_masks_pan_gstin_phone_email_tokens` (unit, table-driven).
- `test_redact.py::test_leaves_ordinary_text_alone` (unit: "Invoice INV-2026-27-012 for Rs 45,000" is
  unchanged).
- `test_redact.py::test_redaction_never_raises` (unit, Hypothesis over arbitrary nested data).
- `test_logging.py::test_nfr025_tokens_never_in_logs` (integration: logs through Django's logger and
  structlog, captures stdout, searches for the token).
- `test_logging.py::test_request_id_bound_and_returned` (integration).
- `test_sentry.py::test_before_send_strips_body_cookies_and_sensitive_values` (unit, synthetic event).
