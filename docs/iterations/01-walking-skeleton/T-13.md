## Why
The profile holds only what the first invoice needs. PAN, GSTIN and bank numbers are stored locked.
Which GST threshold applies depends on the state, and that rule lives in the versioned tax rule
package, not in screen code, so the CA can sign it off (PRD Q20) and other countries can be added later.

## What to build (decisions already made)
**Registry and the rule-set shape (pure Python, no Django).**
- `base.RuleSet` (frozen dataclass): `country_code`, `country_name`, `version`, `currency` (ISO 4217),
  `timezone` (IANA), `format_money(minor_units: int) -> str`, `identifiers: tuple[IdentifierSpec, ...]`
  (each: `name` such as `pan`, label, `required_for_first_invoice`, `validate(value) -> str | None`
  returning the plain error message), `regions` (the state list, or empty), and optional country
  features (for India: `gst_threshold_paise(state_code)`, `tax_year_for(date)`), `None` when a country
  has no such rule.
- `registry.ruleset_for(country_code, on_date=None) -> RuleSet`: the version in force on that date;
  raises `UnsupportedCountry` for any country without a rule set. **There is no default and no fallback
  to India** (FR-005 AC3).
- `registry.supported_countries() -> list[tuple[code, name]]`: `[("IN", "India")]` in production.
- Test-only `XA` ("Testland", currency `XTS`, time zone `Pacific/Auckland`, one identifier `tax_id`, no
  regions, no GST): registered only through the `fake_country` fixture. `XB` is never registered and is
  used to prove fail-closed.

**Indian rule set.** `bhq/rules/india/v2026_1/`:
- `RULESET_VERSION = "in-2026.1"`; currency `INR`; time zone `Asia/Kolkata`; identifiers `pan`
  (required for the first invoice), `gstin` (optional), `ifsc` (bank); regions = the state list;
  `money.py`: rupees with Indian digit grouping (`Rs 20,00,000` in plain text, `₹` in HTML).
- `states.py`: every Indian state and union territory with its GST state code (01–38 and 97), name,
  and `special_category_services: bool`. Working list (PRD A12, CA to confirm before any real invoice):
  Manipur, Mizoram, Nagaland, Tripura are `True`; all others `False`. A module docstring says
  "Working list pending CA sign-off (PRD Q20)".
- `gst.py`: `registration_threshold_paise(state_code) -> int`: 10,00,000 rupees (100,000,000 paise) for
  special-category states, else 20,00,000 rupees (200,000,000 paise).
- `tax_year.py`: `tax_year_for(date) -> "2026-27"` (April to March).
- `identifiers.py`: `is_valid_pan(s)` (`^[A-Z]{5}[0-9]{4}[A-Z]$` after upper-casing and stripping
  spaces), `is_valid_gstin(s)` (15 characters: 2 digits, a valid PAN, 1 entity digit/letter, `Z`, 1
  check character; verify the official GSTIN check-digit algorithm), `is_valid_ifsc(s)`
  (`^[A-Z]{4}0[A-Z0-9]{6}$`). Bank account number: 9 to 18 digits.

**Models (architecture 6.2, inheriting `WorkspaceScopedModel`, forced RLS).**
- `BusinessProfile`: `workspace` (one-to-one, primary key), `legal_name`, `entity_type`
  (`individual`, `sole_prop`; companies later per D15), `pan_enc`, `gstin_enc` (via `EncryptedValue`),
  `state_code` (nullable until entered), `trading_name`, `handles` (JSON list of
  `{"platform": "instagram"|"youtube", "handle": "..."}`), `invoice_prefix` (nullable; set with invoices
  in iteration 4), `default_terms_days` (nullable; S-23 in iteration 2), `rules_version`, `version`.
- `BankAccount`: `id`, `workspace`, `account_number_enc`, `ifsc`, `holder_name`, `is_payout` (partial
  unique: one payout account per workspace), `version`.
- `OpeningTotal`: `workspace`, `tax_year` ("2026-27"), `amount_paise` (BIGINT, >= 0); unique
  `(workspace, tax_year)` (FR-023 data; the threshold total that uses it arrives in iteration 4).

**Actions (all through T-06's runner).** Every Action and Selector below gets the workspace's rule set
with `ruleset_for(workspace.country_code)`; validation messages and field lists come from it.
- A field the rule set does not declare (for example PAN in `XA`) is refused by the Action with
  "This detail is not used in your country." and never stored (FR-003 AC5).
- `profile.save_basic` (`edit_business_profile`): legal name, entity type, state, trading name, handles,
  opening total for the current tax year. Summary "You updated your business profile (<fields>)".
- `profile.add_pan` / `profile.add_gstin` (`change_pan_gstin`, `context.first_entry=True`): allowed only
  when the field has never been saved in this workspace (an `ever_set` check against the activity log
  or a boolean column `pan_ever_set`/`gstin_ever_set` on the profile; use the columns, they are cheaper
  and survive log filtering). If it was ever set, the Action refuses with `StepUpRequired` (the change
  flow arrives in iteration 2; FR-003 AC4 second half). Summary "You added your PAN" (never the value).
- `profile.add_payout_bank` (`change_payout_bank`, `first_entry=True`): same first-entry rule (column
  `payout_bank_ever_set`). Summary "You added your bank account for invoices".
- Validation errors raise a `ValidationError` with the plain messages the screens show, for example
  "That PAN does not look right. It should be 5 letters, 4 numbers, 1 letter." (S-02 wording).

**Selectors.**
- `profile.selectors.profile_view(workspace_id, actor)`: legal name, trading name, the identifier and
  region fields **the rule set declares** (state name only if it has regions), `gst_threshold_paise`
  only if the rule set has that feature (from the rules package for the saved state), handles, and **masked** PAN
  (`ABCDE****F`), GSTIN (first 2 and last 3), bank (`****` + last 4) with IFSC and holder name. Full
  values are never returned by any Selector in this iteration. For a non-owner actor the sensitive part
  is `None` (FR-004 AC3 groundwork; there are no non-owners in the MVP, tested with a fake membership).
- `profile.selectors.missing_for_first_invoice(workspace_id) -> list[str]`: from the rule set's
  `required_for_first_invoice` identifiers plus legal name, region (if any) and payout bank. For India:
  empty when legal name, PAN, state and payout bank exist; GSTIN is never required (FR-003 AC1 in part).

## Acceptance criteria
- **FR-003 AC2 (verbatim):** Given a PAN in the wrong format, when saved, then it is refused with a plain
  message.
- **FR-003 AC3 (verbatim):** Given a state with the lower GST threshold, when saved, then the threshold
  used in FR-150 is the lower one. (Here: `profile_view` reports Rs 10,00,000 for Mizoram and
  Rs 20,00,000 for Maharashtra, from the rules package; FR-150 consumes the same function in iteration 4.)
- **FR-003 AC1 (in part):** Given a new creator with no GSTIN who saved name, PAN, state and bank
  details, when `missing_for_first_invoice` runs, then it returns an empty list.
- **FR-003 AC4 (first half):** Given a new creator entering bank details for the first time, when they
  save, then no second check is asked and the entry is logged; given they try to add a bank account
  again through the first-entry Action, then it is refused with `StepUpRequired`.
- Given saved PAN, GSTIN and bank number, when the rows are read with raw SQL, then none of the three
  appears in plaintext, and no log entry summary contains them (NFR-004).
- Given two workspaces, when profiles are read in A's context, then B's profile, bank account and
  opening total are invisible (NFR-023).
- **FR-005 AC3 (verbatim):** Given a workspace whose country has no rule set (test-only), when any tax,
  invoice or currency rule is looked up, then it fails with an error and nothing is calculated, shown
  or sent; it never falls back to India. (Here: `ruleset_for("XB")` raises, and `profile_view` and
  `missing_for_first_invoice` for an `XB` workspace raise `UnsupportedCountry` rather than return
  Indian fields.)
- **FR-003 AC5 (verbatim):** Given a workspace whose country is not India, when profile setup or
  settings open, then no PAN, GSTIN, Indian state or GST threshold is shown or applied. (Here, at data
  level for `XA`: `profile_view` and `missing_for_first_invoice` contain none of them, money is
  formatted in `XTS`, and `profile.add_pan` is refused; T-14 checks the screens.)
- Given the Indian rule set, when read, then currency is `INR`, time zone `Asia/Kolkata`, and PAN, GSTIN
  and IFSC are its identifiers.
