# T-03: AC-traceability report

**Tier:** B
**Links:** Architecture section 20.1 ("AC traceability: script that lists PRD acceptance criteria with
no test named after them; shown in the report; blocks the release of the iteration it belongs to"),
section 21 (test naming rule), ADR-019.
**Depends on:** T-01.

## Why
"Tests are the contract." The owner should be able to see, per iteration, that every acceptance
criterion it promised has a test, without reading the tests.

## Files to touch
- `app/scripts/ci/ac_trace.py`
- `app/scripts/ci/tests/test_ac_trace.py`
- `app/scripts/ci/tests/fixtures/prd_sample.md` (small PRD extract for tests)
- `.github/workflows/ac-trace.yml` (separate file from `ci.yml` to avoid conflicts with T-02)
- `docs/iterations/01-walking-skeleton/acs.yaml` (the list this iteration claims; contents below)

## What to build (decisions already made)
- **Reading the PRD** (`docs/02-prd/PRD.md`):
  - FR acceptance criteria: under a heading line starting `**FR-NNN `, every bullet matching
    `- AC<n>:` or `- AC<n> (v1):` becomes the ID `FR-NNN-AC<n>`, with its release taken from the FR
    heading (`MVP`, `v1`) unless the bullet says `(v1)`.
  - NFR acceptance: each row of the tables in PRD section 8 (`| NFR-NNN |`) becomes `NFR-NNN`.
    NFR-001 to NFR-024 that the PRD does not repeat (for example NFR-001, NFR-023) live in the table in
    section 7 of `docs/01-usecases/use-cases.md`; read that table too. If both documents have a row,
    the PRD row wins.
  - Ignore headings and bullets inside fenced code blocks.
- **Reading the tests:** scan `app/**/test_*.py` with Python's `ast` (not regex over text) for
  function names matching `^test_(fr|nfr)(\d{3})(?:_ac(\d+))?_`. `test_fr001_ac2_...` covers
  `FR-001-AC2`; `test_nfr025_...` covers `NFR-025`. Case-insensitive. Parametrised tests count once.
- **Iteration claims:** `docs/iterations/<NN>-*/acs.yaml` has two lists: `complete:` (IDs this
  iteration delivers in full) and `partial:` (IDs started here, each with `finished_in: <iteration>`
  and a one-line note).
- **Output:** a Markdown report (written to the job summary, `$GITHUB_STEP_SUMMARY`, and printed) with:
  (1) this iteration's `complete` IDs, each with its test names, or "MISSING"; (2) `partial` IDs with
  their notes; (3) totals for all MVP ACs: covered / not yet covered, grouped by FR area.
- **Exit code:** non-zero only if an ID in the current iteration's `complete` list has no test, or an
  ID in `acs.yaml` does not exist in the PRD (typo guard). Uncovered ACs that no iteration has claimed
  are informational only.
- **Which iteration is current:** `--iteration 01` argument; the workflow passes the highest-numbered
  folder under `docs/iterations/`.
- `ac-trace.yml` runs on push and pull request; it is a required check before an iteration's release
  tag (T-16) and shows as a normal check on PRs.

## Acceptance criteria
- Given the fixture PRD with FR-900 AC1–AC2 and NFR-901, and tests named `test_fr900_ac1_x` and
  `test_nfr901_y`, when the script runs, then FR-900-AC2 is reported uncovered and the other two covered.
- Given an `acs.yaml` whose `complete` list contains an ID with no test, when the script runs, then it
  exits non-zero and the report says "MISSING" next to that ID.
- Given an `acs.yaml` containing `FR-999-AC1` (not in the PRD), when the script runs, then it exits
  non-zero naming the unknown ID.
- Given `- AC9 (v1):` under an MVP FR, when parsed, then that AC's release is v1.
- Given the real PRD at the end of this iteration, when the job runs, then it passes.

## Out of scope
- Checking that a test actually asserts the AC (the reviewer does that).
- Use-case acceptance criteria other than the NFR table. Tagging releases (T-16).
