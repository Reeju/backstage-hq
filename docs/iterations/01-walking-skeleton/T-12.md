# T-12: App shell, empty Home and read-only activity log

**Tier:** B (UI from approved mockups)
**Links:** Mockups **S-05** (Empty state), **S-20** (Normal and Empty states, read-only), shell rules in
`docs/04-design/design-system.md` ("Shell", "State pattern", "Accessibility checklist");
NFR-007, NFR-041; FR-213 (display of entries); architecture section 25 (CSP).
**Depends on:** T-06 (activity log Selector). Uses T-04's `/w/<id>/` routing.

## Why
Every later screen sits inside the same frame: top bar and side menu on desktop, header and bottom
bar on a phone. This ticket turns the mockup shell into Django templates once, plus the two simplest
screens, so the owner can see the workspace and its log.

## What to build (decisions already made)
- **Shell** exactly as design-system "Shell", minus what does not exist yet:
  - Desktop (900 px and up): top bar with logo, workspace name, avatar initials; sidebar with section
    labels. **Only built screens appear:** WORKSPACE: Today; REVIEW: Activity log; SETTINGS: Profile.
    No search field, no counts, no "Waiting" pill until those features exist (a disabled search box
    would promise something that does not work).
  - Phone: header with logo mark, page title or Back, avatar; bottom bar with Today and More (More
    opens a sheet with Activity log, Settings: profile, Sign out). No magnifier until iteration 13.
  - Workspace display name: profile trading name, else legal name, else the user's display name, else
    "Your workspace".
  - Skip link, landmarks (`header`, `nav`, `main`), visible 3 px focus ring, 44 px targets.
- **Home `/w/<id>/`** shows S-05's Empty state heading "Welcome, <first name>. Nothing to do yet." with
  the line "Your workspace is ready. Connecting Gmail and adding deals arrive in the next updates."
  (S-05's "Connect Gmail" and "Add a deal" buttons are not shown until those features exist).
- **Activity log `/w/<id>/activity`**: read-only list from `audit.selectors.recent_entries` (newest
  first, 50 per page with "Older" link): actor label, plain-words summary, time in the workspace time
  zone ("Today 4:32 pm", "3 Nov"). Empty state from S-20. No filters, no Undo, no detail view yet.
- **CSP** (`django-csp`): `default-src 'self'`; `script-src 'self' 'nonce-…'`; `style-src 'self'`;
  `img-src 'self' data:`; `font-src 'self'`; `frame-ancestors 'none'`; `form-action 'self'`;
  `base-uri 'none'`. Alpine uses its CSP build; HTMX with `htmx.config.allowEval = false` and no
  `hx-on` attributes; no inline event handlers. No external CDN or Google Fonts.
- Templates use Django auto-escaping only; no `|safe` on user data (the reviewer checks).

## Acceptance criteria
- Given a signed-in owner on a 390 px wide screen, when Home opens, then the phone header and bottom bar
  show, the empty-state heading greets them by first name, and no link points to an unbuilt screen.
- Given a 1280 px wide screen, when Home opens, then the top bar and the sidebar with Today, Activity log
  and Profile show, and there is no search field.
- Given a workspace with log entries, when the activity log opens, then entries show newest first with
  actor label, summary and local time; given none, then the S-20 empty state shows.
- Given any page, when its response headers are read, then a CSP header with a nonce is present and
  every `<script>` tag carries that nonce.
- Given the pages, when checked with axe (Playwright, in T-14's e2e run) or the HTML test below, then
  every image has alt text or `aria-hidden`, the skip link exists, and headings are in order (NFR-041).
