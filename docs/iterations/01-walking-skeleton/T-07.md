# T-07: Field encryption with per-workspace keys

(Revised for CR-001, 2026-11-11.) Small change: the KMS adapter takes a generic encryption context, and a
**platform data key** encrypts user-level secrets that belong to no workspace (the authenticator seed in
T-11; ADR-005 as amended, C7). AWS KMS stays the key service, used from DigitalOcean (ADR-022).

**Tier:** A (encryption; architecture section 12 says the crypto helper is a tier-A ticket)
**Links:** NFR-004; ADR-005; architecture sections 6.1 (`_enc` columns), 11.1 (third lock), 12.
**Depends on:** T-04.

## Why
PAN, GSTIN, bank account numbers (and later message bodies and files) must be unreadable in a
database dump or backup. Each workspace has its own data key, locked by a master key in AWS KMS that
our code never sees. A ciphertext copied into another workspace's row must refuse to decrypt.

## What to build (decisions already made)
- **`WorkspaceKey`** (architecture 6.2): `workspace_id` primary key, `wrapped_dek` bytes,
  `key_version` int, `created_at`. Forced RLS. Created by `crypto.create_workspace_key(workspace_id)`
  inside the workspace-creation Action (T-10 calls it; until then tests call it directly).
- **`kms.py`:** a `KmsClient` protocol with `generate_data_key(context: Mapping[str, str]) ->
  (plaintext, wrapped)` and `decrypt(wrapped, context) -> plaintext`. Callers in `crypto.py` pass
  `{"workspace_id": "<uuid>"}` for workspace keys and `{"scope": "platform"}` for the platform key; no
  other context is allowed (a `ValueError` otherwise).
  - `AwsKms`: boto3 `GenerateDataKey` (`AES_256`) and `Decrypt` with the context; key ID from settings.
  - `LocalKms`: AES-256-GCM wrap under `LOCAL_KMS_MASTER_KEY` (32 random bytes, base64, from env), with
    the context as associated data. For local and CI only.
  - `checks.py`: a Django system check that is an **error** when `KMS_BACKEND="local"` with
    `DEBUG=False` and settings module `production` or `staging`.
- **`crypto.py`:**
  - `encrypt_field(workspace_id, table, column, row_id, plaintext: str) -> bytes` and
    `decrypt_field(workspace_id, table, column, row_id, blob: bytes) -> str`.
  - AES-256-GCM (`cryptography` AESGCM), random 12-byte nonce per encryption.
  - Associated data: `b"bhq:v1|" + workspace_id + "|" + table + "|" + column + "|" + row_id` (all
    lower-case strings).
  - Blob layout: `0x01` (format version) + `key_version` (2 bytes, big-endian) + nonce (12) +
    ciphertext with tag.
  - Plaintext data keys cached in process memory for 5 minutes (LRU, max 1,000 workspaces); never
    logged, never written to disk; `repr()` of any key holder shows `<redacted>`.
  - `rewrap_workspace_key(workspace_id)`: decrypts the data key and wraps it again (same key, fresh
    KMS wrap); used when the KMS master key rotates. Existing ciphertexts keep working.
  - Errors raise `DecryptionError` with no plaintext, key or ciphertext in the message.
- **Platform key (user-level secrets).** `PlatformKey` (global table, no RLS): `key_version` primary
  key, `wrapped_dek`, `created_at`. `crypto.encrypt_user_field(user_id, table, column, plaintext) ->
  bytes` and `decrypt_user_field(...)` use the newest platform key (created on first use), the same blob
  layout, and associated data `b"bhq:v1|user|" + user_id + "|" + table + "|" + column`. A ciphertext for
  one user or column fails for another. Same cache, redaction and error rules as workspace keys.
- **`fields.py`:** `EncryptedValue(column="pan_enc")` descriptor for models inheriting
  `WorkspaceScopedModel`: reading `obj.pan` decrypts `obj.pan_enc` using `obj.workspace_id`, the model's
  `_meta.db_table`, the column name and `obj.id` (UUIDv7 set before save, so the row ID is known);
  writing `obj.pan = "..."` encrypts; `None` stays `None`. Also `mask(value, keep_start, keep_end)`
  helper for display (`ABCDE****F`, `****7890`).

## Acceptance criteria
- Given a value encrypted for workspace A, table T, column C, row R, when decrypted with the same four,
  then the original returns.
- Given that ciphertext, when decrypted as workspace B, or another row, column or table, then
  `DecryptionError` is raised (third lock).
- Given a ciphertext with one byte flipped, when decrypted, then `DecryptionError` is raised.
- Given a workspace key re-wrapped with `rewrap_workspace_key`, when old ciphertexts are decrypted, then
  they still return the original.
- Given a model field written through `EncryptedValue`, when the row is read with raw SQL, then the
  plaintext appears nowhere in the row (NFR-004).
- Given settings with `KMS_BACKEND="local"` and the staging or production settings module, when
  `manage.py check` runs, then it fails.
- Given an encryption error, when its message and `repr` are inspected, then no key or plaintext
  appears.
- Given a value encrypted with `encrypt_user_field` for user U and column C, when decrypted for another
  user or column, then `DecryptionError` is raised; for U and C, the original returns.
- Given `AwsKms`, when a data key is generated for a workspace or for the platform, then the call carries
  exactly `{"workspace_id": ...}` or `{"scope": "platform"}` as encryption context.
